A 300-level player error (typically HLS.js / HTML5 Media Error 3 or VAST 300) in VidCore’s embed player indicates a media decoding/playback error or CORS/stream manifest load failure.

VidCore works in Microsoft Edge because Edge comes pre-packaged with proprietary media codecs (like Widevine DRM hooks, AAC, and Dolby audio/video pass-throughs) and handles third-party cookies/iframes without extra Electron restrictions.

Electron's default session drops third-party iframe requests and lacks specific Chromium widevine/codec flags by default.

Why VidCore Fails in Electron while VidKing Works
VidCore relies on Native Codecs / DRM / WebAssembly: VidCore’s underlying HLS stream often uses audio or video codecs (like AAC-LC or AC-3 audio streams) or WebAssembly workers that Electron restricts unless explicitly enabled.

Strict Third-Party Cookie & Isolation Rules: VidCore checks for valid local storage / session tokens inside the iframe. Electron blocks cross-origin iframe storage by default.

Electron Security Defaults (CORS & User-Agent): VidCore explicitly blocks requests whose User-Agent identifies as "Electron".

The Fix: Electron Main Process Configuration
Update your Electron main window setup and network session interception in main.ts or main.js:

1. Configure BrowserWindow WebPreferences
Ensure third-party storage, plugins, and web security parameters match standard Chrome:

TypeScript
// main.ts
import { app, BrowserWindow, session } from 'electron';

function createWindow() {
  const mainWindow = new BrowserWindow({
    width: 1280,
    height: 720,
    webPreferences: {
      nodeIntegration: false,
      contextIsolation: true,
      webSecurity: false, // Prevents CORS blocks on nested HLS manifest calls inside the iframe
      allowRunningInsecureContent: true,
      experimentalFeatures: true, // Enables underlying media features
    },
  });

  mainWindow.loadURL('http://localhost:3000');
}
2. Disguise User-Agent & Inject Origin/Referer Headers
VidCore checks request origins and rejects default Electron User-Agents. Forcharge the session headers to mimic Chrome:

TypeScript
app.whenReady().then(() => {
  const filter = { urls: ['*://*.vidcore.*/*', '*://*.vidking.*/*'] };

  // 1. Spoof User-Agent globally so player scripts treat Electron as Google Chrome
  const chromeUserAgent = 'Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/124.0.0.0 Safari/537.36';
  session.defaultSession.setUserAgent(chromeUserAgent);

  // 2. Intercept and rewrite request headers for VidCore
  session.defaultSession.webRequest.onBeforeSendHeaders(filter, (details, callback) => {
    details.requestHeaders['User-Agent'] = chromeUserAgent;
    details.requestHeaders['Referer'] = 'https://vidcore.io/';
    details.requestHeaders['Origin'] = 'https://vidcore.io/';
    callback({ requestHeaders: details.requestHeaders });
  });

  createWindow();
});
3. Enable Proprietary Codecs via Command Line Switches
Place these flags before app.whenReady() at the very top of your Electron main process file:

TypeScript
// Add at the top of main.ts before app.on('ready')
app.commandLine.appendSwitch('autoplay-policy', 'no-user-gesture-required');
app.commandLine.appendSwitch('disable-site-isolation-trials');
app.commandLine.appendSwitch('ignore-certificate-errors');
React <iframe /> Component Setup
In your React frontend, ensure the iframe allows all necessary permissions and media features:

TypeScript
export const VidCorePlayer = ({ embedUrl }: { embedUrl: string }) => {

Summary Checklist for Electron
Set webSecurity: false inside the Electron webPreferences so VidCore's iframe can make cross-origin .m3u8 segment fetches.

Override setUserAgent so VidCore doesn't serve a broken fallback player to Electron binaries.

Rewrite Referer and Origin headers to [https://vidcore.io/](https://vidcore.io/).
